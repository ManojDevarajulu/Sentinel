Sentinel is an open-source static code intelligence engine, dependency visualizer, and **native Claude Code Skill**. Designed for developers and autonomous AI coding agents, Sentinel maps complex TypeScript, JavaScript, and Python repositories into deterministic dependency graphs, calculates the **blast radius** of proposed code modifications, and renders Archify-grade interactive HTML visualizations without any cloud infrastructure or database daemons.

## The Problem: AI Agents Refactor Blindly

When AI coding assistants (Claude Code, Cursor, Codex) refactor code or review Pull Requests, they typically inspect only the active file or immediate prompt context. They lack whole-repository architectural visibility:
1. **Hidden Cascading Failures:** Modifying a seemingly harmless utility or model silently breaks 13 upstream components across 3 hops.
2. **Heavy SaaS Friction:** Legacy tools require PostgreSQL migrations, Redis task brokers, Celery workers, Docker services, and cloud accounts just to answer: *"Who imports this file?"*
3. **Manual Diagram Toil:** Static visualizers require authors to hand-write diagram coordinates or prompt-engineer LLMs to guess architectures.

**Sentinel** treats codebase intelligence as a **deterministic static systems problem**: polyglot AST traversal parses real import/export syntax, builds an in-memory directed graph, computes reverse-reachability blast radius in `< 5ms`, and outputs a self-contained, interactive single-file HTML viewer.

## Quickstart (Zero Dependencies Required)

Sentinel runs on Python 3.10+ using only standard library modules:

```bash
# Clone the repository
git clone https://github.com/ManojDevarajulu/Sentinel.git
cd Sentinel

# 1. Scan your current repository and open the interactive visualizer
python sentinel.py scan . --out architecture.html --open

# 2. Audit the upstream blast radius of modifying a specific file
python sentinel.py blast-radius --changed src/types.py --open

# 3. Audit active Git changes against origin/main before committing
python sentinel.py git-diff --base origin/main --out pr_audit.html --open
```

## 3. Installation & Standalone CLI (Graphify & Archify Experience)

Sentinel runs 100% locally on your machine with **zero login, zero sign-up, zero API keys, and zero cloud dependencies**.

### Installation

```bash
# Clone and install globally/locally via pip
git clone https://github.com/ManojDevarajulu/Sentinel.git
cd Sentinel
pip install .
```

Once installed, the `sentinel` command is directly available anywhere in your terminal.

---

### CLI Commands

#### A. Instant Local Visualizer Server (`sentinel serve`)
Spins up a lightweight built-in HTTP server, scans the codebase in milliseconds, and automatically opens the interactive architecture canvas in your default browser:

```bash
# Serve interactive architecture visualizer for current repo on port 7331
sentinel serve .

# Serve another project directory on a custom port
sentinel serve /path/to/project --port 8080
```

#### B. Full Architecture Scan & Standalone HTML Export
Scan any repository and generate a single-file, zero-dependency HTML viewer:

```bash
# Scan current directory and open interactive visualizer
sentinel scan . --out architecture.html --open

# Output raw JSON architectural summary
sentinel scan . --json
```

#### C. Blast-Radius Audit on Specific Files
Audit the upstream ripple effect of modifying one or more files:

```bash
sentinel blast-radius --changed src/types.py src/graph_engine.py --out blast.html --open
```

#### D. Automated Git Diff Audit (Pre-Commit / Pre-PR)
Evaluate the blast radius of your active Git changes against `origin/main`:

```bash
sentinel git-diff --base origin/main --out pr_audit.html
```

## 6. Known Limitations

1. **Dynamic String Imports**: Computed import paths (e.g. `import(dynamicPath)`) cannot be statically resolved without runtime symbol execution.
2. **Third-Party External Packages**: Sentinel focuses on **internal repository architecture**; imports from `node_modules` or Python standard libraries are treated as external boundaries.
3. **Monorepo Sub-Packages**: Inter-package symlinks require valid `tsconfig.json` `paths` or `package.json` workspaces for cross-package boundary resolution.
